## Перед первой задачей

Предусловия и кто их обеспечивает:

- организация GitHub на плане Team (защита веток приватного репозитория) и окружения `staging` и `production` в репозитории (Settings → Environments) — админ организации заказчика;
- приглашение разработчика с ролью Admin на репозиторий — админ организации; секрет `GITLEAKS_LICENSE` (бесплатный ключ на gitleaks.io) — разработчик, в секреты репозитория;
- проекты Supabase staging и production (регион Frankfurt), проект Vercel, организация Sentry в регионе EU — по `docs/release.md`, «Настройка один раз»; на Free-плане Supabase из `config.toml` убирается `[auth.sessions]` (B00-T04).

Порядок старта: ветка `block/B00-setup` — первой, до правок. Если задачи ведутся в ClickUp — сначала `.claude/rules/clickup.md.example` → `clickup.md` с номером списка, префиксом и тем, кто меняет статусы: без него карточки не завести. ## Зачем

Подготовить репозиторий, окружения и дизайн-систему, чтобы первая задача продукта шла сразу по полному циклу: preview-ссылка в PR, зелёный CI, проверка экранов.

## Как показать

1. Открыть staging (адрес ветки `main` в Vercel): главная в цветах выбранного стиля, светлая и тёмная тема. Preview-ссылка PR — для разработчика.
2. Войти тестовым пользователем (пароль и код второго фактора) — открывается защищённая главная.
3. В GitHub: `main` защищён, CI зелёный.
