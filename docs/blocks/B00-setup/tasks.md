Правку `.github/workflows/*` хук плагина `dev-kit` пропускает только с подтверждением человека, а дифф PR разработчик читает перед слиянием. `CODEOWNERS` с обязательным ревью `.github/**` — включить, когда появится второй разработчик. Секреты окружений вносятся в B00-T04; полный список настроек — `docs/release.md`, «Настройка один раз», п. 3.

## [ ] B00-T07 Безопасность периметра

Требования: — · Подзадача: <ссылка>

**Что делаем.** CSP шаблона уже строгий во всех директивах, кроме `script-src 'self' 'unsafe-inline'` (`next.config.ts`): App Router вставляет в каждую страницу 9 инлайн-скриптов (тема, загрузчик Turbopack, данные серверных компонентов `__next_f`), которые без nonce не разрешить, а `experimental.sri` покрывает только внешние файлы — проверено в шаблоне (спайк D-075 Finance Hub: с `script-src 'self'` плюс SRI — 9 нарушений и нет гидратации; с nonce в `proxy.ts` на статических страницах Cache Components nonce в разметку не попадает — 22 нарушения). Решение проекта — один из двух вариантов:

- **(а) Оставить `'unsafe-inline'` для скриптов.** Страницы остаются статическими оболочками, защита от XSS ложится на экранирование React, `connect-src 'self'` и `frame-ancestors 'none'`.
- **(б) Nonce** по руководству Next.js «Content Security Policy» (`node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`): `proxy.ts` генерирует nonce на запрос и ставит его в заголовок CSP запроса и ответа, `script-src 'self' 'nonce-…' 'strict-dynamic'`, каждая страница рендерится на сервере на запрос (`await connection()` в корневом layout), статическая оболочка и Partial Prerendering не используются — для приложения, где все экраны за входом и зависят от пользователя, потеря невелика, а `'use cache'` для справочников продолжает работать. Для финансовых данных рекомендуется (б).

У варианта (б) пять обязательных частей — без них он не собирается или молча снимает проверки:

1. **`export const instant = false` в корневом layout.** Одного `await connection()` мало: сборка падает на `/_not-found` и требует эту строку.
2. **Замена предохранителя `<Suspense>`.** С `instant = false` сборка перестаёт ловить страницу, которая читает данные вне `<Suspense>` (в варианте (а) это ошибка сборки): такая страница проходит все проверки, а пользователь при переходе смотрит на старый экран, пока не ответит база. Замену задача делает сама. Первое — правило линтера «в `src/app/**/page.tsx` нет `async` и `await`»: страница только собирает экран, данные читает компонент под `<Suspense>`. Сейчас ни одна страница шаблона его не нарушает; это локальное правило `local/*` в `eslint.config.mjs` с пробой в `tests/lint-rules/fixtures`. Второе — e2e на каждую страницу из `SIGNED_IN_PAGES` «заголовок виден до прихода данных»: `instant()` из `@next/playwright`, в production-сборке e2e — `experimental.exposeTestingApiInProductionBuild` по переменной окружения.
3. **Nonce в `ThemeProvider`** (проп `nonce` у next-themes): сам Next подписывает только свои скрипты и `<Script nonce>`, инлайн-скрипт темы — нет.
4. **`style-src` остаётся `'self' 'unsafe-inline'`:** sonner вставляет `<style>` без nonce, инлайн-стили React тоже.
5. **Бюджет JS — по манифестам сборки:** в `package.json` `"budget": "node scripts/bundle-budget.mjs --source manifest"`. У динамических страниц пререндеренный HTML пуст, и обычный замер останавливается с «нет JS»; база и лимит те же.

`form-action 'self'` — только при входе паролем (при OAuth браузер применяет его и к редиректу на провайдера). Заголовки безопасности проверяются по preview-ссылке PR, после слияния блока — на staging; HSTS с `preload` — когда домен окончательный. Cloudflare Access (проверка его JWT в `src/proxy.ts`, закрытый `*.vercel.app`) — когда домен заведён на Cloudflare; нет домена — отдельной задачей после B00, здесь только заголовки.
**Результат.** Выбранный вариант записан строкой D-NNN; браузер выполняет только скрипты приложения (при (б) — только с nonce); с Access — без входа через периметр приложение недоступно.
**Как проверить.** `npm run gate` зелёный: `tests/e2e/ui-quality.spec.ts` на каждой странице не видит в консоли ни одного нарушения CSP (ожидаемый заголовок — список `CONTENT_SECURITY_POLICY` в `tests/e2e/support/page-quality.ts`, он сверяется целиком; при (б) обновить его, а `script-src` сравнивать по образцу с nonce). До слияния блока заголовки смотрят по preview-ссылке PR: `curl -sI <адрес preview>` показывает CSP и остальные заголовки безопасности (если preview закрыт Vercel Deployment Protection, `curl` получит страницу входа Vercel — тогда заголовки ответа смотреть в браузере после входа; Vercel Toolbar на preview — `docs/release.md`, п. 2). При (б): `npm run build` показывает все маршруты динамическими (`ƒ`), `npm run budget` зелёный с прежней базой, `npm run perf` остаётся в бюджете, `npm run lint:rules` подтверждает, что правило про `await` на странице ловит свою пробу, e2e «заголовок виден до прихода данных» зелёный.
