# <Проект>

<Одна фраза: что это за система и для кого.> Стартовая точка — шаблон `nextjs-supabase-template`: Next.js 16 (App Router, Cache Components), Supabase (Auth, Postgres с RLS), строгий TypeScript, shadcn/ui; архитектура «модули и четыре слоя» (README, раздел «Архитектура»).

- [docs/architecture.md](docs/architecture.md) — как устроена система и почему: действующие решения по архитектуре, коду, данным, деньгам и безопасности.
- [docs/README.md](docs/README.md) — карта папки `docs`: где что лежит (документы заказчика — `docs/client/`, настройки сервисов — `docs/ops/`), онлайн-страницы, люди.
- [docs/knowledge/requirements.md](docs/knowledge/requirements.md) — реестр требований заказчика: каждый ответ и решение, статус, раздел спецификации.
- [docs/knowledge/decisions.md](docs/knowledge/decisions.md) — журнал решений; новое решение — строка D-NNN.

- [docs/design/design-system.md](docs/design/design-system.md) — дизайн-система, выбранная заказчиком: цвета, шрифт, состояния, доступность.
- [docs/roadmap.md](docs/roadmap.md) — «Сейчас» и спринты с блоками; блок — папка `docs/blocks/<B01-имя>/` (`README.md` и `tasks.md`).

## Структура

`src/app` — только маршруты и Suspense. `src/modules/<домен>/{domain,application,infrastructure,ui}` + `server.ts` — домены. `src/shared/{domain,infrastructure,lib,ui}` — общее. Зависимости только внутрь (линтер границ). Новый модуль: `npm run new:module <модуль> <запись>`.

## Команды

```bash
npm run dev            # next dev
npm run gate           # «готово» задачи: check + gate:db (advisors, db lint, pgTAP, Squawk) + весь e2e на двух устройствах; нужен supabase start
npm run gate:quick -- <файлы e2e>   # сокращённый набор («Готово»)
npm run check          # всё без базы: линтер, типы, реестр, пределы документов, unit с покрытием, сборка, бюджет JS (состав — package.json)
npm run lint           # next typegen + ESLint 10: strict TypeScript, границы слоёв, защиты денег и доступа (пробы — npm run lint:rules), доступность
npm run typecheck      # next typegen && tsc --noEmit (tsconfig strictest)
npm test               # Vitest: ядро на фейках и компоненты (jsdom); пороги покрытия — vitest.config.mts
npm run test:e2e       # Playwright против production-сборки (без базы сценарии за входом пропускаются)
npm run test:e2e:db    # то же с локальным Supabase — так в CI; один сценарий: -- <файл> --project=desktop
npm run perf           # скорость страниц (tests/perf/pages.ts, 50 тыс. строк); перед закрытием блока и при правке страницы с данными
npm run budget         # JS на маршрут против лимита; npm run analyze — анализ бандла; knip — мёртвый код, jscpd — дубли
npm run req:check      # реестр требований: номера, статусы, непокрытые требования
npm run docs:check     # роли и пределы файлов знаний (.claude/rules/docs.md)
npm run ci:usage       # минуты Actions за месяц и прогноз (CI_INCLUDED_MINUTES — README)
npm run new:module businesses business   # полный срез модуля из scripts/module-template
npm run generator:check   # срез из шаблонов проходит gate и убирается; после правки шаблонов, src/shared, tests/e2e/support, линтера
supabase start         # локальный Supabase; supabase test db — pgTAP; npm run db:check-migrations — Squawk
npm run db:new <имя>   # миграция с lock_timeout и statement_timeout; применить — supabase migration up
npm run db:types       # типы supabase-js из локальной базы (numeric: в Row — number, в Insert и Update — string)
npm run seed:test-user # тестовый пользователь для проверки экранов; npm run totp -s — код второго фактора
```

## Правила работы

- Язык общения — русский, коротко и по делу. На английском — код и комментарии, сообщения скриптов, тесты, коммиты, PR, CHANGELOG, ветки; на русском — интерфейс, документы заказчика и рабочие документы. Комментарий в коде — только если без него не понять причину (`.claude/rules/code-style.md`).
- Правила по областям — `.claude/rules/` (подключаются по путям файлов), подробности — скилы плагина `dev-kit`. API библиотеки, в котором нет уверенности, — документация, а не память: Next — `node_modules/next/dist/docs` (в 16.x менялись API), остальные — Context7 с версией из `package.json`.
- Всё, что заказчик сказал, написал, одобрил или прислал (анкета, сообщение, скриншот, файл, пересказ созвона, ТЗ), — строка в `docs/knowledge/requirements.md` в том же ответе, с подтверждением в чате, какие номера записаны (скил `dev-kit:requirements-register`); наше решение — строка в `decisions.md`.
- Архитектурная развилка посреди задачи — стоп и вопрос человеку с рекомендацией; признаки и что записать после «да» — `.claude/rules/docs.md`.
- Маршрут задачи — быстрый, обычный или полный: Claude называет его с признаком, когда берёт задачу, понижает только человек. Быстрый — `gate:quick`, ревью `medium`, итог в чате без страницы урока и тест-кейсов; полный (вход, права, деньги, миграции, крупная задача) — ещё критик плана, тесты и код разными агентами и одна мутационная проверка.
- Путь задачи — скил `dev-kit:delivery`. Claude проходит шаги сам: тест-кейсы до кода → тест → код (`npm test` по ходу) → `/code-review medium` без цели (уровень — явно; полный маршрут — `high` и агент с промптом `/security-review` на дифф задачи: сама команда незакоммиченное не видит; документы — тоже ревью, крупный — плюс сверка независимым агентом) и проход полноты одновременно с `npm run gate`; находки сверяются с журналом блока `review-log.md`, блокирующие и отклоняемые и правки по ним — агент `dev-kit:finding-verifier` → визуальная проверка агентом `dev-kit:visual-check` в теме по умолчанию → `/dev-kit:explain` → **стоп** с напоминанием: всё в порядке — «задача проверена», есть замечания — напиши их. Замечания — правки, те же проверки, новый разбор и стоп. Только на «задача проверена» — `/dev-kit:task-done`; «ок» и «да» посреди проверки задачу не закрывают. Следующая задача — по «дальше». Перед любым планом — перечитать разделы ТЗ, реестр, решения D-NNN и затронутые разделы `docs/architecture.md`; расхождение с ТЗ — вопрос, не догадка.
- Последняя задача блока — «Закрытие блока»: `/code-review high <номер PR>`, `/simplify <номер PR>`, `/security-review`, `npm run gate` с полным e2e, `npm run perf`, обе темы, `npm run req:check -- --strict` (исключение B00 — в его `tasks.md`), `docs/architecture.md` соответствует коду. PR блока остаётся draft: «Ready for review» и слияние — человек. После слияния Claude обновляет `main` и удаляет слитые ветки.
- Push — только после проверки. Во время задачи нет ни push, ни промежуточных коммитов: на стопе изменения видны в редакторе (Source Control → Changes) вместе с разбором, замечания правятся без коммита. На «задача проверена» `/dev-kit:task-done` делает один коммит `BNN-TNN: …` и push. Исключения: срез из генератора — локальный коммит `wip: BNN-TNN generator slice`; задача, которой нужен CI до проверки, — push с разрешения человека, после приёмки `git reset --soft origin/<ветка блока>` и коммит задачи; `/dev-kit:handoff` отправляет только свой файл; контрольные коммиты перед стопом сворачиваются `git reset --soft <база>`. Красный CI после push — тот же порядок: разбор, подтверждение человека, push.
- Superpowers — по таблице «Superpowers в цикле» скила `dev-kit:delivery`; этот файл важнее их скилов. `brainstorming` — на старте блока (крупный — `spec.md` блока), после одобрения — `README.md` и `tasks.md`, не `writing-plans`; задача из утверждённого `tasks.md` уже одобрена. План — только у крупной задачи: `docs/blocks/BNN-<имя>/plans/BNN-TNN.md` (вне блоков — `docs/plans/<тема>.md`); исполняется по разделу «Исполнение плана» скила `dev-kit:delivery`, не `executing-plans`: чекбоксы шагов, красный тест на шаг, в ветке блока, без ожидания одобрения, worktree и финального ревью ветки. Решения без человека — в «Решения по ходу» в конце плана (их берёт `/dev-kit:explain`); `.superpowers/sdd/` не удалять; новая таблица, модуль или чужой интерфейс — стоп и вопрос. После последнего шага — остаток пути задачи, не `finishing-a-development-branch`; `subagent-driven-development` — по просьбе человека, `requesting-code-review` не используем, параллельные субагенты только читают.
- Тест первым не нужен (заранее одобрено) для конфигов, CI, сгенерированных типов, токенов дизайна и словарей; у миграции тест первым — pgTAP. Ветки: блок — `block/B01-<имя>` (в начале блока, до спеки), правка — `fix/<имя>`, документы отдельной темой — `docs/<тема>`; строка реестра или решение посреди задачи — в текущей ветке тем же коммитом; в `main` напрямую не коммитим. Первый блок — `B00-setup`.
- Проверка экранов за входом — тестовый пользователь (`.claude/rules/tests.md`). В клоне или worktree перед командами с базой — `SUPABASE_PROJECT_ID=<имя папки оригинала>`.
- Остальные `.env*`, `.vercel/**` и `supabase/.env*` Claude не читает (`.claude/settings.json`). Это защита от случайности, не от исполнения кода, поэтому токенов production на машине разработки нет.
- **Готово**: задача — `npm run gate` зелёный; если полный e2e дольше 3 минут — `npm run gate:quick` (`check`, проверки базы и затронутые сценарии), полный прогон — в CI и на закрытии блока; быстрый маршрут — `gate:quick`, задача из одних документов — `npm run check`. Блок — пройдена задача «Закрытие блока».
- Правило, хук, скил или проверка мешают — не обходить молча: назвать в отчёте и предложить изменение; принятое — строка D-NNN и правка шаблона или плагина. Раз в спринт — ретро процесса и уборка документов. Рабочий документ удаляется в задаче, где перестал быть нужен; статус проекта — только «Сейчас» в roadmap; задача вне блока закрывается как задача блока (`.claude/rules/docs.md`, «Жизнь документов»).
- Миграции, `.env*` и lock-файлы Claude правит только с подтверждением (хук плагина). Node 24, npm не ниже 11.19, запрет install-скриптов зависимостей и версий моложе трёх дней — README, «Зависимости и lock-файл».

## Окна и расход CI

- Задача принята — новое окно (исключение — мелкая продолжающая задача, в окне меньше ~100 тыс. токенов); посреди задачи около 200 тыс. токенов — переход на ближайшей логической точке, около 300 тыс. или признаки ухудшения — после текущего мелкого шага. Claude говорит: «сделай `/dev-kit:handoff` и открой новое окно»; `/dev-kit:handoff` и `/dev-kit:resume` запускает только человек.
- В первой сессии недели Claude запускает `npm run ci:usage` и пишет итог одной строкой; прогноз выше двух третей включённых минут — предлагает экономию, например Dependabot раз в месяц (PR, где изменены только документы, Playwright уже пропускает). Бюджет Actions ставит владелец организации.
- Задачи в ClickUp — `.claude/rules/clickup.md` (образец — `clickup.md.example`).
