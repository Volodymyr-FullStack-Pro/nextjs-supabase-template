# Документация и процесс

- Решения: `docs/knowledge/decisions.md` — индекс, строка не длиннее двух предложений. Решение, меняющее архитектуру, стек, процесс, безопасность или деньги, — плюс ADR `docs/knowledge/decisions/D-NNN.md` (контекст, альтернативы, последствия) по шаблону `decisions/_template.md`. Заменённые строки после 100-й уходят в `decisions/archive.md`.
- `CLAUDE.md` — не длиннее 200 строк: только то, чего нельзя вывести из кода; архитектуру не пересказывать.
- Факт о коде проекта (имя файла, команда, правило линтера, образец) живёт в одном месте — в правиле `.claude/rules/` рядом с линтером, который его проверяет. Скил плагина формулирует принцип и ссылается на правило; `CLAUDE.md`, README и задачи блоков указывают на него, а не пересказывают. Нашёл вторую копию — оставить одну и поставить ссылку.
- Новая сущность (таблица, модуль, экран) — три задачи в `tasks.md`: база и pgTAP; ядро и unit-тесты; экран и e2e. Срез целиком создаёт `npm run new:module` в первой задаче отдельным коммитом `wip: BNN-TNN срез из генератора` — он уже проходит `npm run gate`, это доказывает `npm run generator:check`. Дальше каждая задача доводит свой слой под сущность, а её разбор показывает отличия от созданного, а не созданные файлы: (1) миграция, pgTAP, типы; (2) модель, правила, use cases, репозиторий, фейк, unit; (3) форма, список, тексты, e2e. Правка соседнего слоя, без которой `gate` не зелёный (переименована колонка — строка колонок в репозитории), делается в той же задаче.
- Результат задачи пишется один раз — «Итог» под задачей в `tasks.md`; в описание PR и в подзадачу ClickUp уходит тот же текст.

Подробно: путь задачи, блоки, ветки и PR — скил `dev-kit:delivery`; ответы заказчика — `dev-kit:requirements-register`; карточки ClickUp — `dev-kit:clickup-card`.
