# Документация и процесс

- Знания проекта — в `docs/knowledge/`: `README.md` (статус, ссылки, люди), `requirements.md` (реестр требований заказчика), `decisions.md` (индекс решений D-NNN: одна короткая строка), `decisions/D-NNN.md` (ADR для решений, меняющих архитектуру, стек, процесс, безопасность или деньги: контекст, альтернативы, последствия; шаблон `decisions/_template.md`), `open-questions.md` (наши нерешённые вопросы: технические, процесс; вопрос заказчику — строка «открыт» в реестре). После любого решения — строка в индексе; крупное — плюс ADR. Индекс не раздувается: строка ≤ 2 предложений, подробности в ADR, «заменённые» строки после 100-й уходят в `decisions/archive.md`.
- Ответ или решение заказчика из любого канала (анкета, чат, созвон, документ) — строка в `requirements.md` в тот же день: номер, источник, ответ, трактовка, раздел спецификации, статус, ссылка. Спецификация, roadmap, задачи и тесты ссылаются на номера реестра; `npm run req:check` ищет повторы, неверные статусы и требования без ссылки. Утверждать «в спецификации этого нет» можно только после чтения раздела. Подробно: скил `dev-kit:requirements-register`.
- Поставка: `docs/roadmap.md` («Сейчас», спринты, блоки) и папка блока `docs/blocks/<B01-имя>/` (`README.md`, `tasks.md`, у крупного — `spec.md` и `plans/`), заготовки — `docs/blocks/_template/`. Путь задачи, ветки, PR и ClickUp — только в скиле `dev-kit:delivery`.
- Понятия — `docs/glossary.md`: новое понятие из задачи, две фразы, зачем, где у нас; без повторов.
- Разбор изменений перед коммитом — `docs/_scratch/current-diff.md` (не в git, перезаписывается `/dev-kit:explain`).
- Состояние сессии — `.claude/handoff.md` (команда `/dev-kit:handoff` перезаписывает снимок ≤ 80 строк, чтение `/dev-kit:resume`); файл в git, чтобы продолжать с другой машины.
- `CLAUDE.md` — не длиннее 200 строк; только то, чего нельзя вывести из кода; архитектуру не пересказывать.
- Карточки задач (если проект ведётся в ClickUp): параметры в `.claude/rules/clickup.md`, шаблон — скил `dev-kit:clickup-card`.
- Перед PR: `/simplify` → `/code-review` → `/security-review` для auth, денег, миграций (скил `dev-kit:review-checklist`).
