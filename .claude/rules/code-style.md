# Стиль кода

Что можно проверить машиной, проверяет линтер (`eslint.config.mjs`, блок «Стиль кода»): без комментариев в коде, файл ≤ 300 строк (потолок, не цель; за единую ответственность отвечают лимиты на функцию), сложность ≤ 10, вложенность ≤ 3, функция ≤ 80 строк (компонент `.tsx` ≤ 120), ≤ 3 параметров, без магических чисел, имена без сокращений и одиночных букв, kebab-case файлов. Остальное — правила ниже и ревью.

- **Имена говорят, что внутри.** Функция — глагол (`closeMonth`, `listNotes`), данные — существительное (`note`, `rates`), boolean — `is`/`has`/`can` (`isClosed`), компонент — PascalCase, константа модуля — UPPER_CASE с единицей (`SEARCH_DEBOUNCE_MS`, `NOTE_TITLE_MAX`). Без сокращений (`error`, не `err`; `event`, не `e`; `request`, не `req`), без одиночных букв и цифр в именах. Исключения линтера: `_` (не используется), `z` (zod), `err` (конструктор `Result`), идиомы `props`, `ref`, `params`, `ctx`, `env`, `db`, `args`, `dir`, `src`, `dev`, `prod`, `lib`, `config`, `utils` (полный список — `unicorn/name-replacements` в `eslint.config.mjs`).
- **Магических чисел нет.** Любое число, кроме 0, 1, −1 и индексов, получает имя с единицей, даже если встречается один раз: `SEARCH_DEBOUNCE_MS = 300`, `MAX_BODY_BYTES = 1024`, `HTTP_TOO_MANY_REQUESTS = 429` (линтер `no-magic-numbers`, включая значения в объектах: `{ status: HTTP_BAD_REQUEST }`). Числа в JSX-атрибутах линтер не видит — их ловит ревью. Имя и объясняет число, и даёт одно место для правки.
- **Строки, тексты и объекты — по повтору, не ради выноса.** Выносим, когда значение повторяется в двух местах и более или должно меняться сразу везде, и когда это договорённость между частями кода — тег кэша, путь, код ошибки, ключ хранилища: константа или функция рядом с владельцем (`notesTag(userId)`). Не выносим текст интерфейса, который встречается в одном компоненте (без i18n — в разметке, с i18n — в словаре), тестовые данные, классы Tailwind. Где живут константы: в файле, где используются (вверху, UPPER_CASE, без `export`, пока нет второго потребителя); общие для модуля — в его `domain` (правила, лимиты) или `ui/copy.ts` (подписи из нескольких компонентов); общие для проекта — в `shared/domain`. Файлов-свалок `constants.ts` нет.
- **KISS.** Самое простое решение, которое проходит тесты: ранние возвраты вместо вложенных `if`, одна функция — одно действие, объект вместо четырёх параметров, без тернариев в тернариях, без «умных» однострочников. Если функция длиннее экрана — разделить.
- **DRY, но не раньше времени.** Дубли ловит `jscpd` (порог 0 %). Абстракцию заводим на третьем повторе, а не на втором; две похожие функции с разным смыслом — не дубль.
- **YAGNI.** Ничего «на будущее»: нет флагов, параметров и полей без потребителя сегодня; `knip` удаляет мёртвые экспорты; `TODO` в коде не пишутся (комментариев нет) — недоделка живёт задачей в трекере.
- **TypeScript честный.** `any` запрещён везде. `unknown` и `as` — только на границе с внешними данными (`infrastructure`, `shared/lib`, `app/api`, `proxy.ts`), где их тут же превращает в типы Zod (`Schema.parse`); в `domain`, `application`, `ui` и `app` линтер их не пропускает (`as const` можно). `readonly` и `as const` для неизменяемого; `switch` по union — исчерпывающий.
- **Наборы значений без `enum`.** Тип — union строк (`type ExerciseKind = 'reverse' | 'meaning'`). Нужен ещё и список для перебора или проверки — один источник: Zod-схема в `domain` (`export const ExerciseKind = z.enum(['reverse', 'meaning']); export type ExerciseKind = z.infer<typeof ExerciseKind>`) или массив `as const` (`const KINDS = ['reverse', 'meaning'] as const; type Kind = (typeof KINDS)[number]`). Соответствие «значение → текст или настройка» — объект `as const satisfies Record<ExerciseKind, string>`: `satisfies` проверяет, что есть все ключи и нет лишних, а `as const` сохраняет точные значения; аннотация `: Record<…>` их теряет. TypeScript `enum` не используем: лишний код в бандле, не дружит с Zod и строками из базы и API.
- **Неизменяемость.** Не мутировать параметры и внешние объекты; `toSorted`, `with`, spread вместо `sort`/`push` на чужих данных.
- **Ошибки.** Ожидаемые — `Result` (`shared/domain/result`), неожиданные — `throw new Error(...)` с сообщением и `{ cause }`; не глотать исключения пустым `catch` (единственное документированное исключение — `setAll` cookies серверного клиента Supabase, где запись из серверного компонента невозможна по дизайну Next).
- **Асинхронность.** Независимые запросы — `Promise.all`; без `await` в цикле; без «висящих» промисов (`void` только для осознанного fire-and-forget). Async-обработчик в JSX (`onClick={async () => …}`) допустим — ошибку он обрабатывает сам (`try`/`catch` и `toast.error`); `async` без `await` у `'use cache'`, Server Action и серверного компонента — норма Next.
- **Комментариев нет** в `src`, `scripts` и `tests` (корневые конфиги и SQL — можно). Смысл выражается именами, структурой и тестами (`it('rejects an empty title')` — это и есть документация). Линтер запрещает любые комментарии, кроме директив инструментов (`eslint-disable` с именем правила и причиной, `@vitest-environment`). Если без пояснения не обойтись — это сигнал переименовать или разделить функцию; объяснение решения пишется в `docs/knowledge/decisions.md`, не в код.
- **Импорты.** Один блок импортов в начале файла; порядок и группы держит линтер (`simple-import-sort`, чинится `--fix` и на коммите): побочные эффекты (`server-only`, css) → `node:` → react, next, пакеты → `@/shared`, `@/modules` → относительные. Из одного источника — один `import` (`import/no-duplicates`), типы — `import type` или `{ type X }` (`consistent-type-imports`). Короткие импорты даёт не barrel-файл, а точка входа модуля: наружу модуль показывает только `server.ts` и `domain`, потребителю нужны один-два импорта. Barrel-файлов (`index.ts` с реэкспортом) нет: они тянут весь каталог в бандл и dev-сборку и ломают анализ границ и мёртвого кода.
- **Нормализация входа — один раз, на границе.** Текст пользователя приводится к норме в Zod-схеме `domain` через `normalizeText` из `src/shared/domain/text.ts` (`z.string().transform(normalizeText).pipe(z.string().min(1).max(N))`): NFC, без управляющих и невидимых символов, пробелы схлопнуты, края обрезаны. Схема одна у формы и action, поэтому use case, репозиторий и база получают уже чистое значение, повторный `trim` нигде не пишется. Многострочный текст (textarea) — `normalizeMultiline`: переносы сохраняются, лишние пробелы и пустые строки схлопываются. Поисковая строка — `normalizeSearch` в use case. Правило домена поверх чистого значения (например, `hasLettersOrDigits`) — в use case через `Result`.
- **Файлы.** Один смысл на файл; ≤ 300 строк (линтер) — потолок, при котором файл почти наверняка делает две вещи; честно длинный файл с одной ответственностью (справочник, таблица констант) помечается `/* eslint-disable max-lines -- причина */` в первой строке; имя файла — kebab-case и совпадает с главным экспортом (`create-note.ts` → `makeCreateNote`); без barrel-файлов.
